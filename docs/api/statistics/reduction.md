# Data Reduction and Transforms

Tools for reducing the predictors before looking at the outcome, and for
choosing a power transformation of the response (Harrell, *Regression Modeling
Strategies*, §4.7 and Ch. 16):

| Function | Type | Description |
|----------|------|-------------|
| `spearman2_agg` | Aggregate | Generalized Spearman ρ² of a response with a predictor, linear or quadratic in ranks, or categorical (`Hmisc::spearman2`) |
| `hoeffding_d_agg` | Aggregate | Hoeffding's D, a rank measure of dependence of any form, with its P-value (`Hmisc::hoeffd`) |
| `box_cox_agg` | Aggregate | Box–Cox profile likelihood of the power λ with its likelihood-ratio interval (`MASS::boxcox`) |
| `box_cox_transform` | Scalar | `(y^λ − 1)/λ`, `log y` at λ = 0 |
| `box_cox_inverse` | Scalar | `(λz + 1)^(1/λ)`, `exp z` at λ = 0 |
| `varclus_agg` | Aggregate | Hierarchical clustering of the features on a similarity matrix (`Hmisc::varclus`) |
| `redun_agg` | Aggregate | Redundancy analysis: which features are predictable from the others (`Hmisc::redun`) |

The statistics are upstream anofox-regression `reduction` and `transform`,
validated against Hmisc and MASS (`test/sql/reference/reduction_reference.test`,
generated by `validation/generators/make_reference_reduction.R`). Every aggregate
skips rows with a NULL, NaN or infinite value (for the `DOUBLE[]` inputs: a NULL
list or an element that is NULL or not finite) and returns NULL for a group
whose data cannot support a result (too few rows, a constant variable). The
results do not depend on the row order.

```sql
CREATE OR REPLACE TABLE cars AS
SELECT i AS id,
       10 + i * 0.6 + sin(i) * 2 AS mpg,
       100 + i * 9 + cos(i * 1.7) * 15 AS disp,
       60 + i * 6 + sin(i * 0.9) * 12 AS hp,
       1.5 + i * 0.07 + cos(i * 2.3) * 0.2 AS wt,
       16 + sin(i * 0.5) * 2 AS qsec,
       CASE WHEN i % 3 = 0 THEN 'four' WHEN i % 3 = 1 THEN 'six' ELSE 'eight' END AS cyl
FROM range(1, 41) t(i);
```

## spearman2_agg

```text
spearman2_agg(y DOUBLE, x DOUBLE [, options]) -> STRUCT
spearman2_agg(y DOUBLE, x VARCHAR [, options]) -> STRUCT
```

The R² of `rank(y)` on rank terms of `x`: with `p = 1` (default) the squared
Spearman correlation, with `p = 2` the ranks of `x` and their squares, which
detects non-monotone association. An `x` with fewer than three distinct values
uses `p = 1`. With a `VARCHAR` `x` the predictor is categorical
(`spearman2(factor(x), y)`): the R² of `rank(y)` on the level dummies. Use it to
screen predictors and spend degrees of freedom where the association is strong,
without looking at the form of the association.

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `p` | INTEGER | 1 | 1 (ranks) or 2 (ranks and squared ranks); ignored for a categorical `x` |

**Returns:** `rho2`, `adjusted_rho2` (`1 − (1 − ρ²)(n − 1)/df2`), `statistic`
(the F statistic), `df1`, `df2`, `p_value`, `n`, followed by the unified test
fields (`method` = `Spearman rho^2`, `estimate` = `rho2`, `effect_size` = `rho2`;
`alternative`, `conf_low`, `conf_high`, `conf_level` are NULL). At least three
rows are needed.

```sql
SELECT round(s.rho2, 4) AS rho2, s.df1, round(s.p_value, 6) AS p
FROM (SELECT spearman2_agg(mpg, hp, {'p': 2}) AS s FROM cars);

SELECT round((spearman2_agg(mpg, cyl)).rho2, 4) AS rho2_cyl FROM cars;
```

## hoeffding_d_agg

```text
hoeffding_d_agg(x DOUBLE, y DOUBLE) -> STRUCT
```

Hoeffding's D scaled by 30 as in Hmisc (range −0.5 to 1; large values mean
dependence of any form, including non-monotone) and its asymptotic P-value
(Blum, Kiefer and Rosenblatt, Hmisc's `phoeffd` table, bounded below by 1e-8).
Needs at least five complete rows; the cost is O(n²).

**Returns:** `d`, `p_value`, `n` and the unified test fields (`method` =
`Hoeffding's D`, `statistic` = `estimate` = `d`).

```sql
SELECT round(h.d, 4) AS d, h.p_value < 0.05 AS dependent
FROM (SELECT hoeffding_d_agg(qsec, wt) AS h FROM cars);
```

## box_cox_agg

```text
box_cox_agg(y DOUBLE [, x DOUBLE[] [, options]]) -> STRUCT
```

The Box–Cox profile log-likelihood `−n/2 log RSS(λ)` of the linear model of a
positive `y` on `x` (intercept only without `x`), computed on `y` divided by its
geometric mean, as `MASS::boxcox(lm(y ~ x))`. `lambda_hat` maximises the profile
within the range of the grid; the interval is `{λ : ℓ(λ) ≥ ℓ(λ̂) − χ²₁(level)/2}`.
A non-positive `y` is an error.

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `lambdas` | DOUBLE[] | `seq(-2, 2, 0.1)` | Grid of λ for the reported profile; λ̂ and the interval are searched within its range |
| `confidence_level` | DOUBLE | 0.95 | Level of the likelihood-ratio interval |
| `fit_intercept` | BOOLEAN | true | Add an intercept to `x` |
| `eps` | DOUBLE | 0.02 | Below this `|λ|` MASS's series for `log y` is used |

**Returns:** `lambda_hat`, `ci_lower`, `ci_upper` (NULL when the profile stays above
the cut up to that end of the grid), `confidence_level`, `max_log_likelihood`,
`lambdas`, `log_likelihood` (the profile on the grid) and `n_observations`.

Transform with the estimate (often rounded to an interpretable value such as 0,
0.5 or 1), and back with `box_cox_inverse`. A back-transformed fitted value is a
median, not a mean, on the original scale.

```sql
SELECT round(b.lambda_hat, 3) AS lambda, round(b.ci_lower, 3) AS lo, round(b.ci_upper, 3) AS hi
FROM (SELECT box_cox_agg(mpg, [wt, hp]) AS b FROM cars);

SELECT id, round(box_cox_transform(mpg, 0.5), 4) AS z,
       round(box_cox_inverse(box_cox_transform(mpg, 0.5), 0.5), 4) AS mpg_back
FROM cars ORDER BY id LIMIT 3;
```

`box_cox_transform(y, lambda)` raises an error for a non-positive `y` or a
non-finite `lambda`; `box_cox_inverse(z, lambda)` returns NULL where `λz + 1 ≤ 0`
has no real inverse. Both return NULL for NULL input.

## varclus_agg

```text
varclus_agg(x DOUBLE[] [, options]) -> STRUCT
```

The similarity of every pair of features, clustered hierarchically on
`1 − similarity` (R's `hclust`, with its merge, tie-breaking and order
conventions). Features in one cluster are candidates for a single summary score
(e.g. their first principal component with `pca_agg`). The data are complete
rows (Hmisc uses pairwise-complete correlations when values are missing).

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `similarity` | VARCHAR | `spearman` | `spearman`, `pearson` or `hoeffding` (30 × Hoeffding's D, not transformed) |
| `trans` (alias `transform`) | VARCHAR | `square` | Transformation of a correlation: `square`, `abs` or `none` |
| `method` (alias `linkage`) | VARCHAR | `complete` | `complete`, `single`, `average`, `mcquitty`, `median`, `centroid`, `ward.d`, `ward.d2` |
| `cut_height` | DOUBLE | none | Also return the cluster of each feature after cutting the tree at this height (`cutree(h = )`) |
| `feature_names` | VARCHAR[] | `x1, x2, ...` | Names of the features |

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `variables` | `VARCHAR[]` | Feature names |
| `similarity_matrix` | `DOUBLE[][]` | The similarity matrix, one list per feature (`similarity` is a keyword in DuckDB 2.0) |
| `merges` | `BIGINT[][]` | The `p − 1` merges in R's convention: `-j` is feature `j`, `k` the cluster formed at step `k` |
| `height` | `DOUBLE[]` | `1 − similarity` at each merge |
| `dendrogram_order` | `BIGINT[]` | Features (1-based) in dendrogram order |
| `clusters` | `BIGINT[]` | Cluster (1-based, numbered by first feature) of each feature; NULL without `cut_height` |
| `n_observations` | `BIGINT` | Rows used |

```sql
SELECT v.merges, v.clusters
FROM (SELECT varclus_agg([mpg, disp, hp, wt, qsec],
                         {'cut_height': 0.3, 'feature_names': ['mpg', 'disp', 'hp', 'wt', 'qsec']}) AS v
      FROM cars);
```

## redun_agg

```text
redun_agg(x DOUBLE[] [, options]) -> STRUCT
```

Redundancy analysis: predict every feature from all the others with flexible
expansions (restricted cubic splines, dummies for categorical features), remove
the best-predicted one while its R² exceeds `r2` and every feature removed
earlier stays predictable from those kept, and repeat. Constant features are
left out (`too_few`).

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `r2` | DOUBLE | 0.9 | A feature is redundant when its R² from the others exceeds this |
| `type` | VARCHAR | `ordinary` | `ordinary` or `adjusted` R² |
| `nk` | INTEGER | 3 | Spline knots for numeric features (0: linear; 3 to 7) |
| `tlinear` | BOOLEAN | true | Predict only the linear part of a spline feature |
| `rank` | BOOLEAN | false | Numeric features enter linearly (Hmisc sets `nk = 0`) |
| `qrank` | BOOLEAN | false | Numeric features enter as their ranks and squared ranks |
| `allcat` | BOOLEAN | false | A categorical feature also needs every dummy predicted above `r2` |
| `types` | VARCHAR[] | all `spline` | One of `spline` (alias `numeric`), `linear` (as `I(x)`) or `categorical` (level codes, as `factor(x)`) per feature |
| `feature_names` | VARCHAR[] | `x1, x2, ...` | Names of the features |

**Returns:** `variables`, `kept` (in input order), `removed` (in the order
removed), `r_squared` (of each removed feature when removed), `r_squared_later`
(at each removal after the first, the R² of the features removed before it from
those still kept), `r_squared_first` (each feature's R² from all others at the
first step, NULL for a constant feature), `too_few` and `n_observations`.

```sql
SELECT r.removed, r.kept, list_transform(r.r_squared, lambda v: round(v, 3)) AS r2
FROM (SELECT redun_agg([mpg, disp, hp, wt, qsec],
                       {'r2': 0.8, 'feature_names': ['mpg', 'disp', 'hp', 'wt', 'qsec']}) AS r
      FROM cars);
```

## Not available yet

`Hmisc::areg` and `transcan` (optimal transformations) are upstream too, but they
return per-row transformations of a fitted model that cannot be rebuilt from a
stored STRUCT yet, so they are not exposed.
